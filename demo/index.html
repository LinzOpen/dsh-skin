Turn the theme on.

The whole attack is this

input#apikey[value^="s"]  { background-image: url(collect/?apikey=s); }
input#apikey[value^="k"]  { background-image: url(collect/?apikey=k); }
input#apikey[value^="sk"] { background-image: url(collect/?apikey=sk); }
… one rule per prefix, for every character you care about

An attribute selector matches on the value that is there. A match paints a background. Painting a background makes a request. Nothing else is required — and there is no CSS feature you can turn off to stop it, because every part of it is CSS working exactly as designed.

Being precise about scope, because it matters: this reads attribute values, not the live .value property. That still covers server-rendered fields, hidden CSRF tokens, data-* attributes, title, href, and any framework or password manager that mirrors input into the attribute — React and Vue both do, in common configurations. The API key field above has a checkbox to mirror as you type, so you can watch it stream; the other three leak with no help at all.

One honest limit, visible in this very demo: a browser only fetches a background image when the element is actually painted. Off-screen or display:none elements are safe. A real attacker sidesteps this by hanging the selectors on things that are always painted — html, body, a toolbar — which is why the panel scrolls into view when you turn the theme on. css-guard blocks the stylesheet either way; the network request is the payload, and it is refused before it can exist.

Use it

Before you inject anything

import { validateCss } from "css-guard";

const report = validateCss(userStylesheet);
if (!report.ok) {
  return refuse(report.findings);   // rule, line, and why
}
inject(userStylesheet);

Works in the browser, in Node, in a worker, in an extension. It never touches the network and never reads a file unless you hand it a directory.

In CI

npx @css-guard/cli validate themes/
# exit code 1 on any error — that is the gate

In an Electron app

import { createSkinHost } from "@css-guard/electron";
// registers a protocol, serialises insertCSS,
// and refuses anything the linter rejects
